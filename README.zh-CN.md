# ESP8266EX + PDI E2266FS092 照片墨水屏

[English](README.md) | **简体中文**

本固件将 ESP8266EX 和 PDI E2266FS092 2.66 英寸三色墨水屏组合成一台
Wi-Fi 照片显示器。浏览器负责照片解码、裁切、缩放和原生分辨率转换。
默认算法直接移植自微雪官方 Wi-Fi 示例的抖动处理，同时保留最初的两种
Floyd-Steinberg 算法；黑白块面模式仍属于实验功能。网页界面为中文。
ESP8266 最终只接收两个各 5,624 字节的压缩图像平面。

## 首个公开版本

`v1.0.0` 是本项目的首个公开源码版本，包含网页编辑器、微雪抖动移植、两种
最初 Floyd-Steinberg 算法、局域网 API/TCP 控制、带认证 OTA、mDNS、iPhone
快捷指令中转，以及已校准的手机预览。刷写设备前请根据 `secrets.example.h`
编译属于你自己的固件。

## 主要功能

- 在浏览器中完成照片解码、裁切、双指缩放、旋转、尺寸转换和抖动处理
- 微雪官方抖动，以及最初的黑白和三色 Floyd-Steinberg 算法
- 实体屏幕刷新前并排比较四种算法效果
- 内置屏幕校准图，并按浏览器保存黑色/红色校准参数
- 网页清屏、已存画面重刷、IP 地址画面和三档按键操作
- 局域网 HTTP API、8266 端口 TCP 控制、mDNS 和带认证的 OTA
- 支持从 iPhone 照片快捷指令上传，并在浏览器中继续编辑

## 硬件

| 部件 | 型号与要求 |
| --- | --- |
| 主控 | **Espressif ESP8266EX**，4 MB Flash；Arduino 开发板目标为 Generic ESP8266 Module |
| 墨水屏 | **Pervasive Displays (PDI) E2266FS092**，2.66 英寸，296x152，黑白红，24 Pin、0.5 mm FPC |
| 墨水屏驱动 IC | **UC8253**，使用屏幕出厂 OTP LUT |
| 升压电流档位 | 本屏使用 **0.47R**；切换档位前必须断电 |
| Arduino Core | ESP8266 Arduino Core 3.1.2 |

固件以竖屏方式使用面板，因此网页画布为 152x296 像素。本项目不是其他
2.66 英寸墨水屏的通用驱动；连接不同屏幕前必须核对准确型号和引脚定义。

微雪算法移植参考并核对了官方
[Floyd-Steinberg 说明](https://www.waveshare.com/wiki/E-Paper_Floyd-Steinberg)，
以及官方
[ESP 驱动板示例](https://files.waveshare.com/upload/5/50/E-Paper_ESP32_Driver_Board_Code.7z)
中的 `Loader_esp32wf/scripts.h`。所检查压缩包的 SHA-256 为：

`d4764983b1e8b1ef8e219d6de0aea3be85c54409e768b0e6f5026e044b48a1f9`

## 配置与编译

1. 将 `secrets.example.h` 复制为 `secrets.h`。
2. 在 `secrets.h` 中填写 Wi-Fi、备用热点和 OTA 认证信息。
3. 以 Generic ESP8266 Module 编译，选择 4 MB Flash 和 1 MB 文件系统。

Arduino CLI 示例：

```sh
arduino-cli compile \
  --fqbn 'esp8266:esp8266:generic:CrystalFreq=26,eesz=4M1M,FlashMode=dout,FlashFreq=40,baud=115200' \
  esp8266-epd-photo
```

Git 会忽略 `secrets.h` 和所有编译后的固件文件，因为固件二进制中会包含
所配置的认证信息。

许可证见 [LICENSE](LICENSE)。

## 连接与上传

1. 让手机和 ESP8266 连接同一个 Wi-Fi。
2. 按住 FLASH 1.5 至 5 秒，在板载 LED 常亮后松开，再访问屏幕显示的 IP。
   在路由器联网模式下也可以打开 `http://epd-photo.local/`。
3. 选择照片，首次使用建议保留默认的**微雪官方抖动**。选择画面比例并按需
   调整裁切，也可以用四图预览比较两种最初 FS 算法和实验模式。
4. 点击**上传到墨水屏**，等待页面显示刷新完成。

如果配置的 Wi-Fi 在 20 秒内无法连接，设备会启动 `secrets.h` 中配置的
备用热点。请访问墨水屏显示的地址；所有照片处理仍在浏览器本地完成。

## 显示行为

- 逻辑画面：152x296 像素，原生竖屏方向
- 面板模式：标准 KWR 全刷，使用出厂 OTP LUT
- 黑色平面：`DTM1 (0x10)`，`1=白`，`0=黑`
- 红色平面：`DTM2 (0x13)`，`0=无红色`，`1=红色`
- SPI 时钟：4 MHz
- 单次上传数据：11,248 字节
- 刷新前将照片画面原子写入 LittleFS
- 画面比例：全屏、原图、1:1、3:4、2:3 和 9:16
- 排版方式：裁剪填满或完整显示留白
- 手动旋转：网页中以 90 度为单位旋转
- 手动裁切：拖动平移、双指缩放、Mac 触控板平移/缩放，并提供按钮操作
- 编辑控件按六个小类折叠显示；每个浏览器都会记住刷新前的展开状态
- 预览有效尺寸：100% 时约 31x60 mm，可按浏览器在 60%-180% 之间校准
- 图像算法：**微雪官方抖动**、**Floyd-Steinberg（最初版）**、
  **三色 FS（最初版）**和可选的**黑白块面（实验）**
- 停止编辑后，四图对比条会用同一裁切生成全部算法预览；点击小图会同时
  切换主预览和待上传画面
- 内置校准图包含黑白红色块、12 级灰阶、1-2 像素线条、棋盘格和红色饱和度色阶
- 屏幕校准参数按浏览器保存在本地，包括黑色阈值和红色灵敏度偏移
- 校准偏移作用于最初 FS 和三色 FS；微雪官方模式刻意绕过这些偏移，确保
  它始终可作为官方算法的原样对照
- 恢复本屏默认值会把两项校准偏移归零
- 微雪模式使用官方 `[0,0,0]`、`[255,255,255]` 和 `[127,0,0]` 调色板，
  使用未加权 RGB 平方距离、从左到右扫描和半强度误差分配（`weight / 32`）
- 微雪模式绕过曝光、锐化、平滑、红色遮罩及所有手动细节控制
- 最初 FS 使用单向、全强度亮度误差扩散，并开放全部手动细节控制
- 最初三色 FS 使用蛇形 RGB 误差扩散，在校准后的黑、白、红之间选择最近颜色
- 实验黑白块面模式在最终 152x296 像素上执行受限百分位曝光、边缘保留平滑、
  高饱和度红色连通区域提取、Otsu 阈值、局部亮度与两轮清理
- 实验模式不执行误差扩散，可减少人像中间调的密集颗粒和虫状纹理
- 实验模式会隐藏所有细节滑杆
- 网页清屏会把屏幕刷成白色，但保留已经保存的照片画面
- FLASH 短按（少于 1.5 秒）：重新显示 LittleFS 中保存的画面
- FLASH 长按（1.5 至 5 秒）：清屏并显示当前 IP 地址
- FLASH 超长按（至少 5 秒）：将屏幕清为全白
- 达到 IP 档位时 LED 常亮，达到清屏档位后 LED 闪烁；松开按键才执行操作
- 每次刷新后都会关闭墨水屏电源
- 保留屏幕标记可避免 ESP8266 重启后重复刷新
- 固件不会发送 OTP 编程命令

短按重刷之前，至少需要成功上传过一张照片。状态接口通过布尔字段 `stored`
报告是否存在已保存画面。

## 局域网 API 与 OTA

HTTP 接口仅面向设备所在的同一 Wi-Fi 或备用热点。修改屏幕的命令会立即返回
`202`；再次发送命令前，应轮询状态接口，直到 `state` 变为 `done` 或 `error`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/status` | 状态、刷新耗时、地址、已存画面、固件版本、运行时间、空闲内存、Wi-Fi 模式和 RSSI |
| `POST` | `/api/frame` | 上传网页使用的 11,248 字节黑色平面+红色平面数据 |
| `POST` | `/api/display/reload` | 重新显示 LittleFS 中保存的照片画面 |
| `POST` | `/api/display/clear` | 清屏但保留已保存照片 |
| `POST` | `/api/display/ip` | 显示当前 IP 地址画面 |
| `POST` | `/api/shortcut/photo` | 接收 iPhone 快捷指令上传的 multipart `photo` 图片 |
| `GET` | `/shortcut?shortcut=1` | 将快捷指令照片载入编辑器，等待手动确认 |

例如，`curl http://DEVICE_IP/api/status` 可读取状态，
`curl -X POST http://DEVICE_IP/api/display/reload` 可重刷已保存照片。

TCP 控制服务监听 8266 端口，每行接受一个大写命令：`STATUS`、`RELOAD`、
`CLEAR`、`IP` 或 `HELP`。它只适合可信局域网，不要通过路由器端口转发暴露到公网。

路由器联网模式下，mDNS 会广播 `epd-photo.local`、80 端口的 `_http._tcp`
和 8266 端口的 `_epd-photo._tcp`。备用热点模式请访问墨水屏显示的地址，
该模式不保证 `.local` 能正常解析。`/api/status` 通过 `hostname` 和 `mdns`
字段报告主机名及 mDNS 是否成功启动。

网页中的**固件 OTA 更新**按钮会打开 `/update`。该页面使用 ESP8266 Core
官方 HTTP OTA 处理器，并启用 HTTP Basic 认证。请使用 `secrets.h` 中配置的
OTA 账号密码；设备接入不可信局域网前应使用唯一凭据。上传当前源码编译生成的
`.ino.bin` 文件。处理器会验证 ESP8266 固件后再重启。OTA 只替换应用固件，
不会删除 LittleFS 中保存的画面。更新过程中不要断电。

## iPhone 照片快捷指令

快捷指令可以出现在照片 App 的分享菜单中：

1. 将输入照片缩放至 800 像素。
2. 转换为 JPEG。
3. 以 multipart 字段 `photo` POST 到
   `http://epd-photo.local/api/shortcut/photo`。
4. 打开 `http://epd-photo.local/shortcut?shortcut=1`。

网页会把照片载入普通编辑器，默认保留微雪算法，并等待用户裁切、缩放、旋转
或切换算法后再点击**上传到墨水屏**。手机必须与 ESP8266 位于同一局域网。
上传源文件上限约为 850 KiB，以适配 1 MB LittleFS；较大的 iPhone 原图必须
先缩放并转换。

## 引脚连接

对于本项目开发板的升压电流电阻选择器，E2266FS092 应使用 `0.47R`。这与面板
参考电路和 UC8253 升压参考值一致。不要为这块屏幕选择 `3R`，并且只能在断电时
切换。

| 信号 | ESP8266 开发板引脚 | GPIO |
| --- | --- | --- |
| BUSY_N | D1 | 5 |
| RESET_N | D4 | 2 |
| DC | D2 | 4 |
| CSB | D8 | 15 |
| SCL | D5 | 14 |
| SDA/MOSI | D7 | 13 |
| IP/操作按键 | FLASH | 0 |

## 实机验证

本项目于 2026-08-07 和 2026-08-09 在 ESP8266EX 与 E2266FS092 实物组合上验证：

- ESP8266 Arduino Core 3.1.2 编译结果：RAM 42,668 字节（53%）、IRAM
  60,891 字节（92%）、程序 Flash 382,268 字节
- USB 烧录和带认证 OTA 均已验证，OTA 后 LittleFS 中保存的画面仍然存在
- 照片全刷、清屏、IP 画面和已存照片重刷均完成，未发生 BUSY 超时；完整刷新
  实测约为 11-16 秒
- 已验证 Wi-Fi 联网、备用热点、`epd-photo.local`、HTTP API 和 TCP 控制
- 浏览器每次上传准确发送 11,248 字节，刷新完成后面板正常断电
- Chrome 已验证四算法预览、裁切、缩放、旋转、算法切换和校准参数变化
- 桌面与 390x844 手机宽度下没有页面级横向溢出；四图预览条会按设计横向滚动

微雪黑白/三色算法和两种最初 Floyd-Steinberg 算法都已用同一测试图片完成
浏览器验证，并已运行在实机固件中。浏览器测试和成功烧录不能替代用户用真实
照片进行最终的实体屏幕对比。

## 恢复

首次写入固件前，应备份设备完整的 4 MB Flash。本仓库刻意不包含设备专属备份
和固件二进制，因为这些文件可能包含 Wi-Fi 与 OTA 认证信息。恢复完整 Flash
镜像时，也会同时恢复其中的文件系统内容。
